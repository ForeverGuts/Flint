## 文件调用关系

```
index.ts
  └─ Harness.run()
       └─ check() → getMergedConfig() → createProvider()
       └─ main(checkResult)
            └─ createRuntime() → Runtime({ llm, session, 子系统注入 })
                 ├─ FLINT_MODE=rpc → runRpcMode(runtime)
                 │    └─ JSON-RPC 请求 → runtime.prompt()
                 └─ REPL → runReplMode(runtime)
                      ├─ TTY → TreeUI（组件树 + InputHandler）
                      └─ 管道 → TerminalUI
Runtime.prompt()（只编排）
  ├─ 命令 / inputHandlers / skill 展开
  ├─ compaction.maybeCompact(history)   ← context/ 子系统
  ├─ memoryStore.render() → system 的 memory 层   ← memory/ 子系统（有条目才注入，压缩碰不到）
  ├─ agentLoop.run(toolMessages)        ← loop/ 子系统
  │    ├─ llm.stream() → token/tool_call
  │    └─ tools.execute()（先跑 parse 校参数、补默认值，再跑 handler；权限检查 via permission）
  └─ session.appendMessage()            ← session/ 子系统

事件流（观测旁路）
  生产端：runtime.ts / loop/agent-loop.ts / context/compaction.ts
    ├─ events.emit(...)                → 离散事件（UI 的"画面"）
    └─ events.trace() / beginSpan()    → 成对 span（观测的"账本"：结构保证配对 + durationMs）
         ↓ PromptEventEmitter.emit() 统一盖 at / seq / turnId
    订阅者（并列，互不干扰）：
      ├─ TreeUI（TTY 组件树）      ← 画面 + prompt_end 实测账
      ├─ TerminalUI（管道模式）    ← 轻量文本
      ├─ SpanCollector（实例一）→ /traces 命令       ← 就地看最近段耗时/成败/正在跑（开箱即用）
      ├─ SpanCollector（实例二）→ trace-log watcher  ← 成段即落 trace.jsonl（FLINT_TRACE=1）
      └─ SpanCollector（实例三）→ 事件库自动捕获     ← tool_call 成段即 recordToolCall 落 .flint/events.jsonl（main.ts 接线）
           三个实例共用 runtime/span-collector.ts 这一份配对代码：消费者互不知情，关掉谁都不影响别人
```
