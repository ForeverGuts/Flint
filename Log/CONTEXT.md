# 上下文与存储：现状整理

> 性质：**给人看的整理**，不是现状快照（不进 `docs:sync` 生成区，数字均由 `src/` 现取）。
> 目的：把「每轮发给模型什么」和「磁盘上存了什么」摆在同一张图上，
> 再把近期讨论出来的问题挂到各自的**位置**上——这样才能看出哪些是同一个病、
> 哪些是各自独立的洞。
> 整理时间：2026-09-23。凡写具体数字，都来自源码常量，不凭记忆。

## 零、一句话

**上下文 = 系统提示词 7 层 + 对话历史视图 + 本轮输入。**
**存储 = 会话树（`sessions/`）+ 项目档案（`.flint/`）+ 全局配置（`~/.flint/`）。**
压缩只改「对话历史视图」这一项，磁盘上的记录一行都不删。

---

## 一、每轮请求包里有什么

一次向模型提问，最终发出去的是三块拼起来的：

```
[ 系统提示词 7 层 ]  +  [ 对话历史视图 ]  +  [ 本轮你输入的这句话 ]
```

### 1. 系统提示词：7 层，越稳定越靠前

层序是刻意排的（缓存友好：稳定的前缀命中率高，改一层只让它后面失效）：

| # | 层 | 装的什么 | 刷新时机 |
|---|---|---|---|
| 1 | `core` | 人设与核心规矩 | 静态 |
| 2 | `tools` | 工具清单（名字 + 描述 + 参数） | 每次现取 |
| 3 | `skills` | 技能列表与依赖标注 | 每次现取 |
| 4 | `project` | `.flint/PROJECT.md` 现状快照 | **每轮现读文件**（唯一没有 store 的一层） |
| 5 | `memory` | **两节**：项目规约（人写的）+ 项目记忆（模型攒的） | 播种时找一次；记忆读内存 |
| 6 | `task` | 任务清单 + 计划模式横幅 | 读内存 `TaskStore` |
| 7 | `summary` | `[对话摘要] …` | 压缩产物 |

几条容易看漏的：

- **`memory` 层里是两节不是一节**：项目规约来自 `AGENTS.md` / `CLAUDE.md`（**人写的**，播种时首命中即停），项目记忆来自 `.flint/memory.md`（**模型攒的**）。权威来源不同，所以分节不合并。
- **`stack`（技术栈画像）和 `commands`（项目命令表）不新开层**，折进同一层里渲染——理由是它们也是"启动播种一次、运行期不回读"。
- **计划模式横幅折进 `task` 层**，但它是**每轮现取**（会中途变的状态）。
- **`task` 只在有未完成项时注入**；空清单 / 全完成 = 不注入（同时它还是 thinking 自动判定的信号）。
- **注入可截、投影不截**：`task` 和 `memory` 注入时都截 2000 字符，但落盘那一份不截（投影必须与解析严格互逆）。

### 2. 对话历史：不是文件里的内容，是一份「视图」

`getMessages()` 做的是：

1. 从当前分支指针回溯到根，拿到这条路径上的全部条目；
2. 找**最后一个** `compaction` 条目，以它的 `firstKeptId` 为界；
3. 视图 = `[那条摘要]` + `从分界线起的所有真实消息`。

所以两件事要分清：

- **被压掉的原文不再进这个视图**（但它们在磁盘上一个字节都没动）；
- 视图还有两种形态，跟着 thinking 开关走：thinking **开**时降级成纯文本（工具结果转成 `[工具 X 结果] …`，空 assistant 轮剔除），**关**时全量结构化回传（`tool_calls` / `tool_call_id` 原样带）。

### 3. 本轮输入

就是你说的那句话（以及 `@文件` 注入的内容——它走的是输入层，不是工具）。

## 二、磁盘上有什么

| 落点 | 是什么 | 进 git 吗 | 谁来写 |
|---|---|---|---|
| `sessions/*.jsonl` | 会话树，append-only | 否 | 每轮追加 |
| `.flint/memory.md` | 模型的长期记忆（推通道） | 否 | memory 工具 |
| `.flint/CHARTER.md` | 行为宪章（写保护闸） | 否 | 契约锁 |
| `.flint/PROJECT.md` | 项目现状快照 | 否 | 归档时同步 |
| `.flint/DEVLOG.md` | 坐标归档流水 | 否 | archive 工具 |
| `.flint/events.jsonl` | 叙事账本（**拉**通道） | 否 | record_event 等 |
| `.flint/tool-calls.jsonl` | 工具调用流水（**拉**通道） | 否 | span 自动捕获 |
| `.flint/snapshots/` | 手动压缩的留档 | 否 | `/compact` |
| `TASK.md` | 任务清单的投影（重启种子） | 否 | TaskStore |
| `trace.jsonl` | 机器流水（trace watcher） | 否 | 自动 |
| `~/.flint/` | 全局配置 + 项目注册表 | — | 配置管理 |

### `sessions/*.jsonl`：一棵树，不是一条线

一行一条，四种条目：`session`（头）/ `message`（对话）/ `compaction`（摘要节点）/ `leaf`（分支指针）。
**只追加，从不改写**——压缩是往里再加一行 `compaction`，不是删掉前面的行。

### `.flint/`：项目档案，被 gitignore

这是**本机私物**，不随仓库共享（项目注册表的注释里明说：把叙事文件拷给别人、对方放进自己项目的 `.flint/` 就完成导入——所以这是**刻意设计**，不是失误）。

两条通道要分清：**推**（`memory.md`、任务清单——每轮自动注入）与**拉**（`events.jsonl` / `tool-calls.jsonl`——平时躺着，只有 `search_events` 命中或 `/events` 时才浮上来）。

## 三、压缩在这张图上的位置

```
每轮提问前
  → history = getMessages()
  → 体积 > 12000 token 或 条数 > 20 ?  ← 触发判据（**体积优先，条数兜底**）
       保留窗口 = 按体积从末尾累加，夹在 [4, 10]
       切割点 = 倒数第 keep 条 → **挪到最近的非 tool 条目** ← 不能切在工具结果上
       待压批 = 切割点之前 − 已经压过的那批
       → 每条截前 200 字拼起来 → 让模型写 ≤400 字摘要（**带上上一版摘要**）
       → appendCompaction(摘要, firstKeptId)   ← 落盘：给会话文件加一行
```

常量与判据自 2026-09-23 起都在 `src/context/compaction-policy.ts`（纯函数）：`CONTEXT_BUDGET_TOKENS = 12000`、`COMPACT_MESSAGE_THRESHOLD = 20`、`DEFAULT_KEEP_RECENT = 10`（仍在 `compaction.ts`，是**缺省保留条数的唯一来源**）、`MIN_KEEP = 4`、`SUMMARY_BUDGET_CHARS = 400`、喂模型时每条仍截 200 字。

**两次入口**：`maybeCompact`（自动，每轮前跑，看阈值）和 `compactNow`（强制，`/compact` 与 fork 摘要用）。两者共用 `compactTo()`——**压的本体是同一份**。

## 四、挂在图上的问题

按「长在哪个位置」分组，才能看出哪些是同一个病。
**A / B / C / E 四条已于 2026-09-23 修掉**（`verify-compaction-policy.ts` 53 项，变异 11 轮全部精准变红）；**D 已于 2026-09-24 修掉**（`verify-file-ledger.ts` 39 项，变异 6 轮）；F / G 仍未做。

### A. 触发判据（`三` 的入口）— ROADMAP 10.8.9 ✅ 已修

**按条数触发，不看体积。** 一条消息可能只有"好的"两个字，也可能是整个文件的内容。
后果两头：3 条超长消息体积已经很大却不触发；200 条极短闲聊根本不占地方却被压了好几轮。
Pi / Codex / DeepSeek **三家都按 token 触发**，flint 是唯一按条数的。

### B. 摘要链（`三` 的产物）— ROADMAP 10.8.7 + 10.8.8 ✅ 已修

两件事其实是一个病的两半：

- **50 字太窄**：用 50 字概括 10 轮对话，几乎必然丢光（10.8.7）；
- **新摘要不吸收旧摘要**：`待压批` 把「已经压过的」整批排除了，所以每压一次，最早那一层信息**整体掉出去**，不是被传承（10.8.8）。

Pi 的新摘要会与已有摘要合并，Codex 直接压整个历史。**flint 是唯一每版丢弃上一版的。**
8 依赖 7：50 字装不下"上一版 + 这一批"，必须先放宽再谈传承。

**已修**：预算 50 → **400 字**（`SUMMARY_BUDGET_CHARS`）；新摘要把上一版**前置**喂进 LLM，
并在提示词里写明"与概括冲突处以新对话为准"（防传话游戏式漂移）。
这个字数上限同时就是**防无限变长**的答案 —— 每一版都受它约束，链子天然有界，不必再叠"摘要的摘要"。

### C. 失败语义（`三` 的 catch）— ROADMAP 10.8.6 ✅ 已修

**确凿的缺陷**：摘要那次模型调用失败时，兜底分支**照常把历史裁掉，但不写那条压缩记录**。
于是下一轮历史整体滚回来 → 又触发 → 又失败，待压的那批从 10 条涨到 20、30……
而且手动按的时候回执会说"这段对话已经被压过了"——**这句话是错的**，真实原因是摘要没生成出来。

**已修**：失败 = `history` 一字不裁 + `failed` 带回原因；手动回执**先判 `failed` 再判 `!summary`**，
两种说法分开；再加**退避**（只有对话又长了 10 条才重试，否则每轮白烧一次摘要调用）；
以及——失败时留档**已经写了**，回执必须明说"留档已写入：…"。

### D. 「碰过哪些文件」— ROADMAP 10.8.11 ✅ 已修

**已修（2026-09-24）**：压缩时从被压消息的 `tool_calls` 抽路径（封闭枚举：write / edit / git_write / trash
→ 改写桶，read / ls → 只读桶），与上一版清单**合并去重**后作为**结构化字段**写进 compaction entry
（`filesModified` / `filesRead`，空清单不写字段），随压缩逐层累积、上限截断丢最老。
runtime 摘要层**确定性拼接**（不托付给摘要模型），无清单时摘要逐字不回退。

flint 原状（数据源判断仍成立）：
`.flint/tool-calls.jsonl` 里其实记着每次 `read` / `write` / `edit` 的参数（路径就在开头），
但那份是 `clip(JSON.stringify(args), 200)` 的**截断**文本，而且是**拉通道 + 全项目粒度**。
⇒ 它能当**数据源**，不能当**功能**：治不了"压久了模型不知道改过哪些文件"，因为那要靠推通道。
真要做，取数点应该放在总线上的 `tool_call` span（`args` 是完整对象）或 agent-loop 那个唯一的执行点。

### E. 切割点可能落在工具结果上 — ROADMAP 10.8.12 ✅ 已查证、已修

Pi 明确规定切割点不能落在工具结果上。flint 的切割点是纯按位置算的（倒数第 N 条），没这层保护。

**查证结论：会出事。** 工具结果**确实逐条落盘**（`runtime.ts` 轮末写 `role:'tool'` + `tool_call_id`）——
`jsonl-storage.ts` 里那句"这条路从未接线"的注释是**过时的**（已订正），照它判断会得出相反的错误结论。
所以"倒数第 N 条"完全可能落在工具结果上，保留窗口第一条就成了没有配对 `tool_use` 的孤儿。

**已修**：`safeCutIndex` 把切割点**往前**挪到最近的非 tool 条目（往后会留下孤儿，是错的）。
代价是保留条数可能多几条 —— **宁可多留，不可造孤儿**。

### F. 新发现：压缩之后，摘要每轮被发两遍

`maybeCompact` 的注释写着「摘要独立返回（不 unshift 进 history，避免污染缓存前缀）」，
但 `getMessages()` 又把那条 compaction 条目渲染成历史数组**首位**的 `[对话摘要] …`。
于是在「压缩完成」到「下一次压缩」之间的每一轮，请求包里**摘要出现两次**：
一次是系统提示词的 `summary` 层，一次是历史首位。

代价很小（50 字 × 2），但它让那句"避免污染缓存前缀"的意图落空了。**未立项，先记在这儿。**

### G. 长期记忆层不随仓库走 — 未立项

DeepSeek 的立场是「规则要写进每次重置都重读的**仓库**文件」。
flint 的 `CHARTER.md` / `PROJECT.md` / `DEVLOG.md` 都在**被 gitignore 的 `.flint/`** 里
⇒ 换台机器克隆仓库，宪章不在；多人协作得人肉同步。
一人用无所谓（个人偏好不污染仓库），协作时是真缺口。

## 五、刻意不做的（别当成洞）

- **自动压缩不留档**：那只是窗口快满了，不是你的意图；留了只会堆出一堆分不清哪次是哪次的 md。
- **留档不回读、不自动清理**：它是给你翻看的副本，不是能还原的备份；删哪份由你定。
- **没有"撤销压缩"**：压缩不可逆。与其给一个按不下去的按钮，不如在按下之前就把原文留好。
- **压缩不删磁盘上的任何一行**：会话文件是 append-only，压缩只加一行。
