# DECISION_RULES — 决策日志书写规则

> 本文件是关键决策日志的**格式规则书**，不包含实际记录。
> AI 在遇到"二选一"或"新方案引入"的场景时，**必须**按此规则将决策过程写入 `Log/DECISION_LOG.md`。

---

## 格式

```
## YYYY-MM-DD — 决策标题
```

每条决策包含以下段落：

| 段落 | 内容 | 是否必需 |
|------|------|---------|
| **场景：** | 描述面临的问题或背景 | 是 |
| **方案 A（方案名）：** | 方案 A 的描述 | 是 |
| **方案 B（方案名）：** | 方案 B 的描述 | 是 |
| **选择：** | A 或 B | 是 |
| **理由：** | 选择该方案的原因（列表） | 是 |
| **代价：** | 选择此方案的负面后果 | 否 |
| **参考：** | 关联的文档链接 | 否 |

决策之间用 `---` 分隔。

## 示例

```
## 2026-07-23 — 选择 Pi 模式（调用方持有循环）

**场景：** 设计 Runtime 的交互循环归属。

**方案 A（Pi 模式）：** Runtime 不持有循环，main.ts 持有 while(true)，runtime.prompt() 只处理单次输入。

**方案 B（CLI 模式）：** Runtime 内部持有循环，runtime.start() 启动后自动进入读→调→印的流水线。

**选择：A**

**理由：**
- I/O 切换成本低（CLI → WebSocket → HTTP 只改 main.ts）
- Runtime 职责纯粹（处理输入，不关心输入来源）
- 测试简单——单次 prompt() 可独立验证

**代价：** main.ts 多了一些模式分发的样板代码。
```

## 输出路径

```
Log/DECISION_LOG.md
```
